Each weekly page follows the same structure so it's easy to scan without reading everything from top to bottom.

## Page structure

Every note begins with a **summary block** — one paragraph capturing the core idea of the week in plain language.

Then comes the detailed content, organized into sections matching the lecture flow:

1. **Concepts** — definitions, mental models, diagrams.
2. **How it works** — the mechanism explained step by step.
3. **Code / schematics** — concrete examples where applicable.
4. **Key takeaways** — the three to five things worth remembering.
5. **Questions** — things I'm still not sure about, for follow-up.

## Conventions

- `Inline code` means a register name, signal name, instruction, or filename.
- Code blocks are annotated with comments explaining what's happening.
- :::note, :::tip, and :::caution callouts mark things the professor emphasized, useful shortcuts, and common mistakes respectively.

## Why public?

Writing for an audience forces clarity. If I can't explain it here, I probably don't understand it well enough yet.
